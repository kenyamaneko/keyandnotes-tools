# 変更判定の仕様 (レビュー用の草稿)

Issue #2 の仕様を、テストケースカタログの形で網羅した草稿。レビューが済んだら、テスト生成とコーディングに進む。コーディングの後に、理由や意図が明確なものを ADR・BDR として提案し、OK が出たものを残して、この文書を削除する。

入力と出力は次のとおり。

- **入力**：比較元、変更後のコミット、除外パス (標準に足すもの)、範囲 (名前とパスの組)
- **出力**：コードの変更があるか。範囲ごとにも出す。出力ファイルに `changed=true|false` と `<範囲名>=true|false` の行で書く

標準の除外パスは、`*.md`・`docs/**`・`rules/**`・`.claude/**`・`.vscode/**`・`.gitignore`・`LICENSE` とする。

比較元には、取り込み先のコミットとプッシュ前のコミットがある。取り込み先のコミットがあるときはそれを使い、なければプッシュ前のコミットを使う。
