# 用語集

ドキュメント・コード・テスト名で使う、ドメインの概念を表す語。

| 用語 | コード | 説明 |
|---|---|---|
| テストケースカタログ | `test_case_catalog` | テストコードが確かめている振る舞いを、機能ごとに一覧にした HTML ページ |
| ケース | `case` | テスト 1 つのこと。1 つ以上のステップを持つ |
| ステップ | `step` | ケースの中の、Given・When・Then の 1 組。ケースは基本的にステップを 1 つだけ持つ。複数ステップを持つのは、シナリオテストと、異常からの回復の確認だけ |
| Given | `given` | ステップの前提となる状態。付けないこともある |
| When | `when` | ステップで確かめる操作。1 つ以上ある |
| Then | `then` | ステップの結果。環境によって結果が違うときは、環境ごとの Then を持つ |
| 種別 | `kind` | ケースが、どこまで実物で動かすかの分類。単体テスト、部品間結合テスト、インフラ結合テスト、サービス間結合テスト、E2Eテスト、シナリオテストの 6 つ |
| 正常異常 | `normal_or_abnormal` | ケースが正常系か異常系か |
| 観点 | `perspective` | ケースの質を見やすくするために付ける分類。境界値、同値分割、エッジケース、件数・有無、外部依存の失敗、回復確認の 6 つ。1 つも付けなくてよく、複数付けてもよい |
| 目次 | `table_of_contents` | カタログで、大機能の見出しへ移動するための一覧 |
| ヘッダーエリア | `header_area` | カタログの画面の上端に固定された、絞り込みボタンなどが並ぶエリア |
| ハイライト | `highlight` | 目次で、いま読んでいる大機能のリンクを目立たせること |
| 環境 | `environment` | シナリオテストを実行する環境。ローカル、dev環境の 2 つ |
| 項目 | `property` | Given・When・Then・種別・正常異常・観点・環境のこと |
| テスト名 | `test_name` | テストの名前。機能名、セパレーター、Given・When・Then をつないだ一文の順に並ぶ (例: `[本体:注文:業務ルール]送料計算 > 注文金額3000円で送料を計算すると、送料は無料になる`) |
| 機能名 | `feature_name` | テスト名の先頭にある `[区分:大機能(:中機能)]小機能`。ケースがどの機能のものかを表し、カタログでは区分・大機能・小機能の見出しになる |
| セパレーター | `separator` | テスト名で、機能名とそれ以降を分ける文字。テストの実行ツールによって異なる。言語によっては、機能名をテスト名と別に持つので、セパレーターはない |
| 区分 | `region` | 機能の一番大きな分類。本体・共通・運用・外部連携・シナリオの 5 つ |
| 大機能 | `major` | 区分の下の機能 |
| 中機能 | `minor` | 大機能の下の切り口。付けないこともある。区分「運用」には付けられない |
| 小機能 | `feature` | 最小単位の機能 |
| 機能の一覧 | `feature_list` | 区分ごとに大機能と中機能を並べたもの。設定ファイルの `features` に書いた順が、大機能と中機能のカタログの表示順になる |
| テスト結果 | `test_result` | テストを実行したツールが出力するファイル。カタログの元になる。実行したテスト 1 つごとに、テスト名と項目を持つ。形式は言語によって異なる (TypeScript・Python・C#・Kotlin は JUnit XML、Go と Dart は JSON) |
| 言語 | `language` | テストコードを書いた言語。TypeScript、Python、C#、Kotlin、Go、Dart の 6 つ。言語によって、テスト結果の中で機能名や項目が載る場所が違う |
| 設定ファイル | `config` | カタログを生成するコマンドに渡す JSON ファイル。タイトル、CSS のファイルのパス、テスト結果のファイルのパスと言語、機能の一覧、コミットを書く |
| コミット | `commit` | カタログの元になったコードのコミット。カタログに表示する |
